# Premium inbox UI redesign with Jivo-style conversation cards

This redesign transforms the inbox conversation list from a basic text-based layout to a premium card interface with gradient avatars, online indicators, and proper visual hierarchy. The changes address scrolling issues, implement a complete card redesign with visitor context (website URL display), and polish the overall UI with consistent spacing and transitions. The work touches only the dashboard frontend component and passes TypeScript compilation.

**Watch for:** Online indicator shows unconditionally (confirmed) — all visitors appear online regardless of actual status. Website URL extraction depends on currentPageUrl which may be null for older conversations (confirmed). Hash-based avatar colors lack collision testing (likely).

**Verdict**: CHANGES_REQUESTED

## High-level view

The scrolling fix establishes proper flex layout hierarchy: the aside gets explicit height, the header becomes non-shrinking, and the conversation list takes remaining space with overflow-y-auto. The conversation cards now use 48px gradient avatars with hash-based color assignment, displaying visitor name, timestamp, website domain, and a 2-line message preview. All interactive elements gained smooth 150ms transitions. The color palette shifted from mixed slate/gray to consistent gray-* variants. The online indicator is hardcoded to show for all visitors without checking actual presence state. Website display falls back through website.name → currentPageUrl domain → "website", which breaks for conversations lacking URL data. Avatar colors derive from a simple string hash without collision avoidance or testing across the visitor dataset.

## Scrolling container hierarchy

## Gradient avatars and online presence

Each conversation card displays a 48px circular avatar with a gradient background. The gradient is selected by hashing the visitor name string and indexing into an 8-color palette:

```typescript
function getAvatarColor(name: string): string {
  const colors = [
    'from-indigo-500 to-indigo-600',
    'from-purple-500 to-purple-600',
    // ... 6 more gradients
  ];
  let hash = 0;
  for (let i = 0; i < name.length; i++) {
    hash = ((hash << 5) - hash) + name.charCodeAt(i);
    hash = hash & hash;
  }
  return colors[Math.abs(hash) % colors.length];
}
```

The hash uses bitwise operations (`(hash << 5) - hash` is equivalent to `hash * 31`) and self-ANDs to keep the value in 32-bit integer range. This produces consistent colors for the same visitor name across sessions, but the distribution across 8 colors is untested. No verification exists to ensure common name patterns don't cluster into one or two colors.

The green online indicator dot (8px with white ring) is rendered unconditionally for every visitor:

```tsx
<span className="absolute bottom-0 right-0 size-2 rounded-full bg-green-500 ring-2 ring-white" />
```

The diff shows `visitorOnline` is referenced in the conversation header ("Visitor online" vs "Visitor"), but the indicator in the card list doesn't check this variable. All visitors show as online regardless of actual socket connection state. **(confirmed issue)**

## Website URL extraction and display

The `getWebsiteDisplay()` utility attempts a three-tier fallback:

```typescript
function getWebsiteDisplay(conversation: InboxConversation): string {
  return 'from ' + (conversation.website?.name || extractDomain(conversation.visitor?.currentPageUrl) || 'website');
}
```

When `website.name` is missing, it extracts the domain from `currentPageUrl` using `new URL()` in a try-catch. When both are unavailable, it returns "from website", which provides no information to the reviewer. Older conversations or visitors who closed their browser before URL tracking initialized will show this generic fallback. The final fallback text could be more explicit about missing data. **(confirmed issue)**

## Conversation card layout and typography

The card structure uses a horizontal flex layout with the avatar on the left (flex-none to prevent shrinking) and content on the right (flex-1 with min-w-0 for text truncation). The content area stacks three sections vertically:

1. Name and timestamp row: name is semibold 15px gray-900, truncates when long; timestamp is 12px gray-500, flex-none to prevent wrapping; unread badge sits in this row
2. Website line: 12px gray-600, truncates on overflow
3. Message preview: 13px gray-700, line-clamp-2 (shows max 2 lines with ellipsis)

Spacing between the avatar and content is gap-3 (12px). Card padding is p-3 (12px on all sides). Hover state adds gray-50 background with 150ms transition. Selected state adds blue-50 background and a 4px blue-600 left border.

The unread count badge changed from gradient background (from-indigo-600 to-purple-600) to solid blue-600, and size changed from dynamic width to fixed size-5 (20px × 20px) to prevent layout shifts when count changes from single to double digits.
